# sENG — адаптивная программа обучения: план внедрения

**Дата:** 2026-09-23  
**Статус:** первый рабочий срез в PR; следующие срезы — план, а не готовые функции.  
**Принцип:** `Understand → Retrieve → Use → Meet it again → Make it automatic`.

## Что уже есть и что не следует дублировать

В приложении уже работают `ts-fsrs@5.4.2`, раздельные очереди новых и назначенных к повторению карточек, ввод английского ответа, Personal Inbox, журнал ошибок, адаптированное/оригинальное чтение с контекстным переводом, базовое аудирование через браузерную озвучку и текстовые задачи на продукцию. Данные обучения пока хранятся локально в браузере.

Нельзя выдавать существующую озвучку за понимание естественной речи, эвристическую проверку письма — за полноценного преподавателя, а самооценку стартового CEFR — за диагностический результат.

## Срез 1 — ежедневный маршрут (в этом PR)

Вместо статической сетки на «Сегодня» показывать объяснимый маршрут по имеющемуся времени (10/15/20/30 минут, ограничение до 60), текущей FSRS-очереди, цели и выполненным активностям.

- Если есть назначенные FSRS-повторения, начать с них; новые карточки не выдавать за просроченные.
- Если назначенных повторений нет, предложить небольшой объём нового материала; самопроверка и будущие интервалы остаются за FSRS.
- Ежедневно давать смысловой input (чтение или аудирование) и output (говорение/письмо). Для 30 минут и более — оба вида input.
- Для общей цели выбирать менее практиковавшийся канал input по прошлым семи дням; для конкретной цели учитывать её. Состояние не должно «прыгать» вслед за выполнением задания в тот же день.
- Засчитывать этап только на основании существующих review/activity/production events, а не факта открытия экрана.
- Оставить ручной доступ ко всем разделам. План — рекомендация, а не жёсткий коридор или штраф за пропуск.
- Не менять существующие даты FSRS из-за чтения, свободной практики или расчёта плана.

**Граница среза:** план открывает существующие упражнения и использует текущую телеметрию. Он пока не измеряет понимание текста, качество произношения или точность самостоятельной речи.

### Приёмка среза 1

1. Очередь due имеет приоритет над новым материалом и не теряется после обновления страницы.
2. Упражнение «чтение/аудирование/производство» ведёт в рабочий модуль.
3. Событие завершения активности отражается на «Сегодня» без фиктивных процентов уровня.
4. Сумма ориентировочных минут соответствует выбранному дневному бюджету.
5. Никакая функция построения плана не изменяет `learner.memory`.
6. На мобильном и десктопе карточки не выходят за пределы экрана; все темы наследуют семантические цвета.
7. `npm run check` включает тесты маршрута, а PR проходит CI до merge.

## Срез 2 — чтение и словарь как единая цепочка

**Путь ученика:** книга/адаптация → попытка понять абзац → выбор незнакомого выражения → контекстный перевод → сохранение в Inbox с исходным предложением → позже активное вспоминание → собственное предложение.

Следует сохранять конкретное значение слова в данном контексте, а не одну «универсальную» словарную карточку для всех значений. У леммы, значения и словосочетания разные идентификаторы. Текущий локальный словарь — первый источник; внешние обращения остаются резервом с индикацией неопределённости. Отдельно маркировать машинный контекстный перевод.

Уровень книги из метаданных — лишь ориентир. Для рекомендаций добавить приблизительную оценку знакомых слов по реальной истории пользователя; не выдавать точный CEFR на основании одного текста. Длительное чтение ради смысла должно оставаться возможным без теста после каждого абзаца.

**Приёмка:** сохранённое из книги выражение появляется в Inbox с исходным предложением и корректной подсказкой на русском; свободное чтение не переносит карточки FSRS на более ранний срок.

## Срез 3 — слушание с уменьшающейся поддержкой

Перейти от коротких TTS-фрагментов к контролируемым по уровню аудиодиалогам, затем к лицензированным естественным записям. Первое прослушивание — без текста; далее по запросу ключевые слова, английская расшифровка и перевод трудного контекста. Завершать лёгкой проверкой понимания нового содержания, а не только нажатием «прослушать».

Нужны время воспроизведения, повторы, версия аудио/транскрипта, признак показанной подсказки и отдельные результаты проверки понимания. TTS остаётся доступной резервной озвучкой; отсутствие звука не должно засчитываться как аудирование.

**Приёмка:** отключение субтитров возможно, ошибки/подсказки сохраняются в соответствующем типе практики, аудио не раскрывает транскрипт автоматически до попытки.

## Срез 4 — продуктивная речь, письмо и ошибки

Развить существующие задания по модели: конкретная коммуникативная цель → самостоятельная попытка → 1–3 значимых исправления → самостоятельное повторное исправление → вариация той же задачи через несколько дней. Повтор задания — отдельное событие от FSRS-повтора слова.

Для речи сначала использовать явно выбранную учеником диктовку/текстовый след; при внедрении записи голоса нужны согласие, индикатор микрофона, удаление и политика хранения. Будущий AI-провайдер — через сервер, с валидируемой структурой ответа и без секретных ключей в клиенте. AI-разбор не считать автоматически объективной оценкой произношения.

**Приёмка:** ошибки превращаются в контекстные повторные задачи; ранняя свободная попытка не сдвигает срок назначенного повторения; продукт различает «неправильно» и «возможно, но менее естественно».

## Срез 5 — диагностика, навыки и доказуемый прогресс

Короткая начальная диагностика должна отдельно проверять лексику, понимание текста, аудирование и базовые грамматические конструкции; речь — отдельная добровольная часть. После 7 и 30 дней использовать новые, ранее не показанные задания на перенос навыка, а не только повтор тех же карточек.

Раздельно хранить доказательства: узнаю написанное / узнаю на слух / вспоминаю по смыслу / пишу / использую в контексте / говорю. Не умножать автоматически FSRS-карточки по каждому навыку: память и языковая компетенция — связанные, но разные модели.

Четыре направления (meaning-focused input, output, language-focused learning, fluency) отслеживать по реальным событиям за 7/30 дней. Баланс — ориентир, не строгие 25% каждого дня. Отображать доверие к оценке и «данных недостаточно» вместо точных процентов без измерения.

## Архитектура и качество

Сначала ввести версионированную схему событий для новых типов заданий: `eventId`, `occurredAt`, `activityKind`, `contentVersion`, `targetIds`, `result`, `helpUsed`, `duration` (когда можно надёжно измерить), `nextTaskDueAt` (для продуктивной задачи, НЕ для FSRS карточки). Существующую историю и локальные настройки мигрировать без потерь; предусмотреть экспорт и импорт до облачной синхронизации.

Автоматические тесты: расчёт дневного маршрута, полночь и локальная дата, отсутствие раннего переноса FSRS, устойчивость после перезагрузки/миграции, сценарии Android/iOS/desktop, клавиатура, accessibility и reduced motion. Для новых обучающих упражнений отдельно тестировать, что ответ не раскрывается раньше попытки и что внешние/AI-сервисы не обязательны для базовой работы.

Контент должен быть версионированным, проверенным на смысл/перевод и законно используемым. Не собирать сомнительные книжные тексты или аудио без подтверждённого права использования.
